SecureLiteLLM Architecture

SecureLiteLLM is a policy hook inside a LiteLLM proxy. It sits between an agent and its model, remembers where content in the conversation came from, and decides whether each tool call the model asks for runs, waits for a person, or is blocked.

1. System components

The teal box is the part this project built. Everything else is the agent around it and the services it calls.

2. AWS deployment

The proxy runs in AWS with no route to the internet. Participants run the demo UI, agent and tool server on their own laptops and reach the proxy over HTTPS from an allow-listed IP.

Where the safety decisions live

  • Before the model call: untrusted tool results are classified and the session remembers taint across turns, so a hidden instruction read early still counts three steps later.
  • After the model call: each generated tool call is judged by its destination. A destination the user named, or one on the deploy-time allowlist, can go; tainted content to an unnamed destination is held or blocked.
  • A person decides the unclear cases: held calls wait in the approvals store; an admin approves or denies, and an approval can be used once.
  • No agent changes: all of it runs inside the proxy; the agent just sees allowed calls, a held notice, or a refusal.
